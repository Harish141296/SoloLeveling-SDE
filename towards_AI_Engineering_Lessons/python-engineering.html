Idiomatic Python & the data model

Senior Python isn't about clever tricks — it's about writing code that reads like the language intends. Python's data model (the dunder methods) is what makes objects feel native.

python
# Pythonic patterns you should reach for by reflex
nums = [1, 2, 3, 4, 5]
squares = [n * n for n in nums if n % 2]        # comprehension, not a loop+append
a, *rest = nums                                  # unpacking
pairs = dict(zip("abc", range(3)))               # build dicts from iterables

# EAFP ("easier to ask forgiveness"): try first, handle the failure
try:
    value = config["timeout"]
except KeyError:
    value = 30

# The data model: make your objects behave like built-ins
class Money:
    def __init__(self, cents): self.cents = cents
    def __repr__(self): return f"Money({self.cents})"
    def __eq__(self, other): return self.cents == other.cents
    def __add__(self, other): return Money(self.cents + other.cents)
Key idea
Prefer comprehensions, unpacking, and EAFP over manual loops and pre-checks. Implementing __repr__, __eq__, and friends makes your classes first-class citizens.

Type hints & static checking

Type hints are optional at runtime but invaluable in real codebases: editors autocomplete, mypy catches bugs before they ship, and they double as documentation. They're also the mechanism FastAPI and Pydantic use for validation.

python
from typing import Optional
from collections.abc import Iterable, Callable

def total(prices: list[float], discount: float = 0.0) -> float:
    return sum(prices) * (1 - discount)

def find(items: Iterable[str], pred: Callable[[str], bool]) -> Optional[str]:
    return next((x for x in items if pred(x)), None)

# Modern syntax (3.10+): X | None instead of Optional[X]
def greet(name: str | None = None) -> str:
    return f"Hello {name or 'world'}"
terminal
pip install mypy
mypy app/            # static type check the whole package
Note
Adopt types gradually — start at module boundaries (function signatures) where they pay off most. Run mypy in CI to keep them honest.

Decorators, generators & context managers

Three constructs separate intermediate from advanced Python. Each wraps a common need into reusable syntax.

  • Decorators — wrap a function to add behavior (logging, caching, auth) without touching its body.
  • Generators — produce values lazily with yield; stream huge data without loading it all into memory.
  • Context managers — guarantee setup/teardown (files, locks, connections) via with.
python
import time
from functools import wraps
from contextlib import contextmanager

def timed(fn):                       # a decorator
    @wraps(fn)
    def wrapper(*args, **kwargs):
        t = time.perf_counter()
        result = fn(*args, **kwargs)
        print(f"{fn.__name__} took {time.perf_counter() - t:.3f}s")
        return result
    return wrapper

def read_lines(path):                # a generator: lazy, memory-friendly
    with open(path) as f:            # context manager: file always closes
        for line in f:
            yield line.rstrip()

@contextmanager                      # build your own context manager
def timer():
    start = time.perf_counter()
    yield
    print(f"elapsed {time.perf_counter() - start:.3f}s")

Async Python with asyncio

For I/O-bound work — calling APIs, querying databases, handling many connections — asyncio lets one thread juggle thousands of waiting operations. It's the foundation under FastAPI and modern Python servers.

python
import asyncio
import httpx

async def fetch(client, url):
    r = await client.get(url)          # 'await' yields control while waiting
    return r.status_code

async def main(urls):
    async with httpx.AsyncClient() as client:
        # run all requests concurrently, not one-by-one
        results = await asyncio.gather(*(fetch(client, u) for u in urls))
    return results

asyncio.run(main(["https://example.com"] * 10))
Key idea
Async helps I/O-bound work, not CPU-bound work. For heavy computation use processes (or hand it to a task queue like Celery — see the Data Stores guide). Never call blocking code inside an async function.

Environments, packaging & tooling

Reproducible projects start with isolation. A virtual environment keeps each project's dependencies separate; pyproject.toml declares them; modern tools keep code clean automatically.

terminal

pip install -e ".[dev]"                              # install your package + dev extras

# Fast, modern tooling
pip install ruff black mypy pre-commit
ruff check .            # lint (replaces flake8/isort, very fast)
black .                 # auto-format
pre-commit install      # run all checks on every git commit

# pyproject.toml — the single source of project truth
[project]
name = "myapp"

[project.optional-dependencies]
dev = ["pytest", "ruff", "mypy"]
Note

Dataclasses, errors & logging

Three everyday tools for clean code: dataclasses for simple data holders, custom exceptions for clear error handling, and logging instead of print.

python
import logging
from dataclasses import dataclass, field

logger = logging.getLogger(__name__)

@dataclass
class User:                          # auto __init__/__repr__/__eq__
    name: str
    roles: list[str] = field(default_factory=list)
    active: bool = True

class PaymentError(Exception):       # specific, catchable errors
    """Raised when a payment cannot be processed."""

def charge(user: User, amount: int) -> None:
    if amount <= 0:
        raise PaymentError("amount must be positive")
    logger.info("charged %s cents to %s", amount, user.name)   # not print()
Key idea
Use logging over print: it has levels, can be configured per environment, and writes structured output you can search in production.

Unit testing fundamentals

Tests are what let you change code without fear. A unit test checks one small piece of behavior in isolation; a good suite is fast, deterministic, and run on every commit. The classic shape is Arrange–Act–Assert.

python
# A pure function is the easiest thing to test
def slugify(text: str) -> str:
    return "-".join(text.lower().split())

def test_slugify_basic():
    # Arrange / Act / Assert
    assert slugify("Hello World") == "hello-world"

def test_slugify_collapses_spaces():
    assert slugify("  a   b ") == "a-b"
  • Test behavior, not implementation — so refactors don't break tests.
  • Each test should be independent and able to run in any order.
  • Aim for the testing pyramid: many fast unit tests, fewer integration tests, a handful of end-to-end.

Pytest in depth

pytest is the de-facto Python test framework: plain assert, powerful fixtures for setup, and parametrization to run one test across many inputs.

python
import pytest

# Fixtures provide reusable, isolated setup (DB, client, temp data)
@pytest.fixture
def cart():
    return {"items": [], "total": 0}

def add(cart, price):
    cart["items"].append(price); cart["total"] += price
    return cart

def test_add_updates_total(cart):          # fixture injected by name
    add(cart, 100)
    assert cart["total"] == 100

# Parametrize: one test, many cases
@pytest.mark.parametrize("price,expected", [(100, 100), (0, 0), (50, 50)])
def test_add_various(cart, price, expected):
    assert add(cart, price)["total"] == expected

def test_rejects_negative(cart):
    with pytest.raises(ValueError):        # assert an exception is raised
        add(cart, -1)
terminal
pip install pytest
pytest -q                      # run quietly
pytest -k "total" -v           # run tests matching a name, verbose
pytest --lf                    # re-run only last failures
Try it
Put shared fixtures in a conftest.py at your tests root — pytest discovers them automatically across all test files.

Mocking, coverage & TDD

To test code that touches the outside world (APIs, time, randomness), you mock those dependencies. Coverage shows what's untested; TDD flips the order — test first, then make it pass.

python
from unittest.mock import patch
import myapp

# Replace a real network call with a fake during the test
@patch("myapp.httpx.get")
def test_get_user(mock_get):
    mock_get.return_value.json.return_value = {"id": 1, "name": "Ada"}
    user = myapp.get_user(1)
    assert user["name"] == "Ada"
    mock_get.assert_called_once()
terminal
pip install pytest-cov
pytest --cov=myapp --cov-report=term-missing   # see exactly which lines lack tests
  • Mock at the boundary — fake the network/DB, test your real logic.
  • Coverage is a guide, not a goal — 90% of meaningful paths beats 100% of trivial getters.
  • TDD loop — red (failing test) → green (make it pass) → refactor.
  • Run tests in CI on every push (see the DevOps & Cloud guide) so nothing regresses.
