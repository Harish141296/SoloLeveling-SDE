From ML to neural networks

A neural network is a stack of simple units. Each unit computes a weighted sum of its inputs, adds a bias, and passes the result through a non-linear activation. Stacking these layers lets the network learn arbitrarily complex functions — the 'deep' in deep learning.

  • Weights & biases — the learnable parameters, adjusted during training.
  • Activations — ReLU, GELU, sigmoid, tanh; the non-linearity is what makes depth useful.
  • Forward pass — input flows through layers to a prediction.
  • Backward pass — the error flows back, and gradients tell each weight how to change.
Key idea
Training = repeatedly: predict, measure error (loss), compute gradients via backprop, nudge weights downhill. That loop is the entire game.

Tensors & autograd

PyTorch's two superpowers: tensors (n-dimensional arrays that run on GPUs) and autograd (automatic differentiation — it builds the gradient computation for you).

python
import torch

# Tensors: like NumPy arrays, but GPU-capable and differentiable.
x = torch.tensor([[1., 2.], [3., 4.]])
print(x.shape, x.dtype, x.device)

# Move to GPU if available
device = "cuda" if torch.cuda.is_available() else "cpu"
x = x.to(device)

# Autograd: track operations to compute gradients automatically.
w = torch.tensor(2.0, requires_grad=True)
y = w ** 2 + 3 * w            # some function of w
y.backward()                  # compute dy/dw
print(w.grad)                 # tensor(7.)  -> derivative 2w+3 at w=2
Note
Autograd is why you never hand-derive gradients. You define the forward computation; PyTorch differentiates it.

Building a model with nn.Module

Models subclass nn.Module: define layers in __init__, the data flow in forward. PyTorch tracks all parameters for you.

python
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, in_dim, hidden, out_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(hidden, out_dim),
        )

    def forward(self, x):
        return self.net(x)            # logits (no softmax here)

model = MLP(in_dim=784, hidden=256, out_dim=10).to(device)
print(sum(p.numel() for p in model.parameters()), "parameters")
Note
Output raw logits, not probabilities. nn.CrossEntropyLoss applies softmax internally — doing it twice hurts training.

The training loop

Every PyTorch model trains with the same five-step loop. Memorize it — you'll write it hundreds of times.

python
import torch.nn as nn

loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

for epoch in range(num_epochs):
    model.train()
    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)

        optimizer.zero_grad()        # 1. clear old gradients
        logits = model(xb)           # 2. forward pass
        loss = loss_fn(logits, yb)   # 3. compute loss
        loss.backward()              # 4. backprop -> gradients
        optimizer.step()             # 5. update weights

    # validation
    model.eval()
    with torch.no_grad():
        correct = sum((model(xb.to(device)).argmax(1) == yb.to(device)).sum().item()
                      for xb, yb in val_loader)
  • zero_grad() — PyTorch accumulates gradients; clear them each step or they pile up.
  • model.train() / model.eval() — toggles dropout and batchnorm behavior.
  • torch.no_grad() — disables gradient tracking for faster, lower-memory inference.

Loss, optimizers & learning rate

Three knobs decide whether training works at all: the loss (what you minimize), the optimizer (how you descend), and the learning rate (how big each step is).

  • Loss — CrossEntropy for classification, MSE/L1 for regression, task-specific losses otherwise.
  • Optimizer — AdamW is the safe default; SGD+momentum can generalize better with tuning.
  • Learning rate — the most important hyperparameter. Too high diverges, too low crawls.
python
# A scheduler decays the LR over training for better convergence.
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=num_epochs)

for epoch in range(num_epochs):
    train_one_epoch(...)
    scheduler.step()        # step the LR schedule once per epoch
Key idea
If a model won't learn, change the learning rate before anything else. Sweep it on a log scale (1e-2, 1e-3, 1e-4) first.

Regularization & generalization

Deep nets have enough capacity to memorize the training set. Regularization forces them to generalize instead.

  • Dropout — randomly zeroes activations during training; prevents co-adaptation.
  • Batch / layer norm — stabilizes and speeds up training.
  • Weight decay — L2 penalty, built into AdamW.
  • Early stopping — stop when validation loss stops improving.
  • Data augmentation — expand the dataset with realistic transforms (flips, crops, noise).
Try it
Train one model with dropout and weight decay, one without. Plot both train and validation curves and watch the gap close.

Convolutional networks (vision)

CNNs exploit the structure of images: convolutional filters detect local patterns (edges → textures → objects), with far fewer parameters than a dense net.

python
import torch.nn as nn

class SmallCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        )
        self.head = nn.Sequential(
            nn.AdaptiveAvgPool2d(1), nn.Flatten(),
            nn.Linear(64, num_classes),
        )

    def forward(self, x):
        return self.head(self.features(x))
Note
In practice you rarely train vision models from scratch — you fine-tune a pretrained ResNet or ViT (see transfer learning below).

Sequences: from RNNs to attention

Text, audio, and time series are sequences. RNNs/LSTMs process them step by step, carrying a hidden state — but they struggle with long-range dependencies and can't parallelize over time.

  • RNN / LSTM / GRU — recurrent state; good intuition, now largely historical for NLP.
  • The problem — long sequences cause vanishing gradients; sequential compute is slow.
  • The fix — attention lets every position look at every other directly, in parallel. That insight became the transformer.
Key idea

Training at scale

Real models need GPUs and the tricks that make them train fast and fit in memory.

  • DataLoader — batching, shuffling, multi-worker loading, pin_memory for fast GPU transfer.
  • Mixed precision — train in fp16/bf16 with torch.amp; ~2× faster, half the memory.
  • Gradient accumulation — simulate large batches on small GPUs.
  • Distributed training — DDP across multiple GPUs/nodes; FSDP/DeepSpeed for huge models.
python
from torch.amp import autocast, GradScaler

scaler = GradScaler()
for xb, yb in train_loader:
    optimizer.zero_grad()
    with autocast(device_type="cuda", dtype=torch.bfloat16):
        loss = loss_fn(model(xb), yb)
    scaler.scale(loss).backward()    # scaled to avoid fp16 underflow
    scaler.step(optimizer)
    scaler.update()

Transfer learning & fine-tuning

You almost never start from random weights. Take a model pretrained on huge data and adapt it to your task with a fraction of the data and compute.

python
import torch.nn as nn
from torchvision import models

# Load pretrained backbone
net = models.resnet50(weights="IMAGENET1K_V2")

# Freeze the backbone, train only a new head
for p in net.parameters():
    p.requires_grad = False
net.fc = nn.Linear(net.fc.in_features, num_classes)   # new trainable head

optimizer = torch.optim.AdamW(net.fc.parameters(), lr=1e-3)
Key idea
Transfer learning is why a team with 1,000 labeled images can build a strong classifier. The same idea underlies LLM fine-tuning (LoRA) in the next guides.

Debugging training that won't learn

Models fail silently — they run but don't learn. A senior engineer has a checklist instead of panic.

  • Overfit one batch first. If the model can't reach ~0 loss on a single batch, there's a bug — not a tuning issue.
  • Check shapes & loss inputs. Logits vs probabilities, label dtype/range, the right loss.
  • Loss is NaN — LR too high, bad data, missing normalization, fp16 overflow.
  • Loss flat — LR too low, frozen params, dead ReLUs, vanishing gradients.
  • Train good, val bad — overfitting: add regularization or data.
Try it
Deliberately set the learning rate to 10 and watch the loss explode to NaN, then to 1e-8 and watch it barely move. Feeling both failure modes builds intuition fast.
