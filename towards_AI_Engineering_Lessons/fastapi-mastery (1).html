What FastAPI is, and why it wins

FastAPI is a modern Python web framework for building APIs. You write ordinary Python functions, annotate the inputs with standard type hints, and FastAPI turns those hints into request parsing, validation, serialization, and live interactive documentation — for free.

Three ideas power everything you will learn here:

  • Type hints are the contract. A hint like price: float isn't a comment — FastAPI reads it to validate the request and document the endpoint.
  • It runs on ASGI. FastAPI sits on Starlette (web layer) and Pydantic (data layer), so it speaks async natively and is genuinely fast.
  • The docs build themselves. Every route you write appears in an interactive UI at /docs with no extra effort.
Note
Mental model: a FastAPI app is a list of path operations. Each one binds an HTTP method + URL path to one Python function. Everything else — validation, auth, docs — hangs off that function's signature.

Install and set up your environment

Always work inside a virtual environment so project dependencies stay isolated. The [standard] extra pulls in the server (Uvicorn) and common helpers.

terminal
# 1. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. Install FastAPI with the standard extras (includes uvicorn)
pip install "fastapi[standard]"

# 3. Confirm it's there
python -c "import fastapi; print(fastapi.__version__)"
Try it
Run pip freeze > requirements.txt now. Pinning dependencies early saves you from “it worked yesterday” bugs later.

Your first app

Create a file called main.py. The variable app is the application; the @app.get("/") decorator registers a path operation for GET /.

main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}


@app.get("/health")
def health_check():
    return {"status": "ok"}

Run it with the dev server (auto-reloads on save):

terminal
fastapi dev main.py
# Then open:
#   http://127.0.0.1:8000          -> your JSON response
#   http://127.0.0.1:8000/docs     -> interactive Swagger UI
#   http://127.0.0.1:8000/redoc    -> alternative ReDoc docs
Try it
Open /docs, expand the GET / endpoint, and click Try it out → Execute. You just called your API from a UI you never had to build.
Note
Returning a dict works because FastAPI serializes it to JSON automatically. You can also return Pydantic models, lists, or primitives.

Path operations & HTTP methods

Each HTTP method has a matching decorator. Use them to mean what they conventionally mean: GET reads, POST creates, PUT replaces, PATCH partially updates, DELETE removes.

main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/items")
def list_items():
    return ["pen", "notebook"]


@app.post("/items")
def create_item():
    return {"created": True}


@app.put("/items/{item_id}")
def replace_item(item_id: int):
    return {"replaced": item_id}


@app.patch("/items/{item_id}")
def update_item(item_id: int):
    return {"patched": item_id}


@app.delete("/items/{item_id}")
def delete_item(item_id: int):
    return {"deleted": item_id}
Try it
Add a @app.get("/items/count") endpoint. Watch how it appears in /docs automatically, grouped under the same path family.

Path parameters

Anything in curly braces in the path becomes a function argument. Add a type hint and FastAPI validates and converts it — a non-integer for item_id: int returns a clean 422 error, not a crash.

main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/{user_id}")
def get_user(user_id: int):          # "/users/abc" -> 422 validation error
    return {"user_id": user_id, "type": str(type(user_id))}

Order matters

Routes are matched top to bottom. Put fixed paths before parameterized ones, or the fixed path will never be reached.

main.py
@app.get("/users/me")        # must come FIRST
def get_current_user():
    return {"user_id": "the current user"}


@app.get("/users/{user_id}")  # otherwise "me" is read as a user_id
def get_user(user_id: int):
    return {"user_id": user_id}

Restrict values with an Enum

main.py
from enum import Enum
from fastapi import FastAPI

app = FastAPI()


class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"


@app.get("/models/{name}")
def get_model(name: ModelName):
    return {"model": name, "value": name.value}
Try it
Hit /models/banana. FastAPI rejects it and — in /docs — renders a dropdown with only the three valid choices.
GET

Query parameters

Function parameters that are not in the path become query parameters automatically. A default value makes them optional; no default makes them required.

main.py
from fastapi import FastAPI

app = FastAPI()

DB = [{"name": "pen"}, {"name": "notebook"}, {"name": "eraser"}]


@app.get("/items")
def list_items(skip: int = 0, limit: int = 10, q: str | None = None):
    # /items?skip=1&limit=2&q=note
    results = DB[skip : skip + limit]
    if q:
        results = [i for i in results if q in i["name"]]
    return results

Booleans and lists

FastAPI coerces query strings intelligently. ?active=1, ?active=true, and ?active=yes all become True. Repeat a key to receive a list.

main.py
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/search")
def search(
    active: bool = False,                       # ?active=true
    tags: Annotated[list[str], Query()] = [],   # ?tags=a&tags=b
):
    return {"active": active, "tags": tags}
Try it
Call /search?active=yes&tags=python&tags=web and confirm the boolean and list both parse correctly.

Request bodies with Pydantic

To accept JSON, declare a parameter whose type is a Pydantic BaseModel. FastAPI reads the request body, validates every field against the model, and hands you a typed object.

main.py
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float
    description: str | None = None    # optional
    in_stock: bool = True             # default


@app.post("/items")
def create_item(item: Item):
    # `item` is a fully validated Item instance
    total = item.price * 1.2          # add 20% tax
    return {"item": item, "price_with_tax": round(total, 2)}
request
// Send this body to POST /items
{
  "name": "Keyboard",
  "price": 49.99
}
Try it
POST a body where price is the string "cheap". You'll get a precise 422 telling you which field failed and why.
Note
Pydantic v2 is the validation engine. The patterns below assume v2, which ships with current FastAPI.

Pydantic models in depth

Pydantic does far more than mark fields required. Use Field for per-field rules and field_validator for custom logic.

main.py
from datetime import datetime
from pydantic import BaseModel, Field, EmailStr, field_validator


class User(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    email: EmailStr                                   # validates email format
    age: int = Field(ge=0, le=120)                    # 0 <= age <= 120
    bio: str = Field(default="", max_length=500)
    signup_at: datetime = Field(default_factory=datetime.utcnow)

    @field_validator("username")
    @classmethod
    def no_spaces(cls, v: str) -> str:
        if " " in v:
            raise ValueError("username cannot contain spaces")
        return v.lower()
Note
EmailStr needs pip install "pydantic[email]". The @classmethod on validators is required in Pydantic v2.

Nested models

Models can contain other models. FastAPI validates the whole tree and documents it.

main.py
from pydantic import BaseModel


class Address(BaseModel):
    street: str
    city: str
    zip_code: str


class Customer(BaseModel):
    name: str
    addresses: list[Address]          # a list of nested models


@app.post("/customers")
def create_customer(customer: Customer):
    return {"cities": [a.city for a in customer.addresses]}
Try it
Add a @field_validator("zip_code") to Address that rejects anything that isn't 5 digits.

Validating query, path & body metadata

Wrap a parameter's type in Annotated[...] with Query, Path, or Body to attach constraints, docs, and examples — the modern, recommended style.

main.py
from typing import Annotated
from fastapi import FastAPI, Query, Path

app = FastAPI()


@app.get("/products/{product_id}")
def get_product(
    product_id: Annotated[int, Path(ge=1, description="Positive product id")],
    q: Annotated[
        str | None,
        Query(min_length=3, max_length=50, description="Search term"),
    ] = None,
    page: Annotated[int, Query(ge=1)] = 1,
):
    return {"product_id": product_id, "q": q, "page": page}
  • ge / gt / le / lt — numeric bounds.
  • min_length / max_length — string length.
  • pattern — a regex the value must match.
  • description / title / examples — show up in /docs.
Try it
Add pattern=r"^[a-z]+$" to q and watch /docs document the rule and the server enforce it.

Form data & file uploads

HTML forms and file uploads use a different content type than JSON. Use Form for fields and UploadFile for files. (Requires python-multipart, included in [standard].)

main.py
from typing import Annotated
from fastapi import FastAPI, Form, UploadFile, File

app = FastAPI()


@app.post("/login")
def login(
    username: Annotated[str, Form()],
    password: Annotated[str, Form()],
):
    return {"user": username}


@app.post("/upload")
async def upload(file: UploadFile, note: Annotated[str, Form()] = ""):
    contents = await file.read()           # bytes
    return {
        "filename": file.filename,
        "content_type": file.content_type,
        "size_bytes": len(contents),
        "note": note,
    }


@app.post("/upload-many")
async def upload_many(files: list[UploadFile]):
    return {"count": len(files), "names": [f.filename for f in files]}
Note
UploadFile streams to a temp file, so large uploads don't exhaust memory. Use await file.read() in an async function.
Try it
Use the /docs file picker on /upload to send a real image and inspect the reported size and content type.

Headers & cookies

Read request headers and cookies by declaring them with Header and Cookie. Header names with hyphens map to underscores automatically (User-Agent → user_agent).

main.py
from typing import Annotated
from fastapi import FastAPI, Header, Cookie

app = FastAPI()


@app.get("/inspect")
def inspect(
    user_agent: Annotated[str | None, Header()] = None,
    x_request_id: Annotated[str | None, Header()] = None,  # reads X-Request-ID
    session: Annotated[str | None, Cookie()] = None,
):
    return {
        "user_agent": user_agent,
        "request_id": x_request_id,
        "session": session,
    }

Response models

Declare response_model to control what the client receives. FastAPI filters the output to the model's shape — perfect for hiding fields like password hashes.

main.py
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    email: EmailStr
    password: str          # accepted on input...


class UserOut(BaseModel):
    username: str
    email: EmailStr        # ...but password is NOT in the output model


@app.post("/users", response_model=UserOut)
def create_user(user: UserIn):
    # Even though we return the full object, FastAPI strips `password`
    return user
  • response_model_exclude_unset=True — omit fields that kept their default.
  • response_model_exclude={"email"} — drop specific fields.
Try it
Return the full UserIn object and confirm the password never reaches the client — the response model is the gatekeeper.

Status codes

Set the default success code per route with status_code. Use the status module instead of magic numbers.

main.py
from fastapi import FastAPI, status

app = FastAPI()


@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item():
    return {"created": True}


@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int):
    return None        # 204 means "no body"
Note
Need a dynamic code? Inject the Response object and set response.status_code inside the function.

Error handling

Raise HTTPException to return a controlled error. The detail becomes the JSON error body.

main.py
from fastapi import FastAPI, HTTPException, status

app = FastAPI()
DB = {1: "pen", 2: "notebook"}


@app.get("/items/{item_id}")
def get_item(item_id: int):
    if item_id not in DB:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Item {item_id} not found",
            headers={"X-Error": "ItemMissing"},
        )
    return {"item": DB[item_id]}

Custom exception handlers

Translate your own exceptions into clean responses app-wide.

main.py
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()


class OutOfStock(Exception):
    def __init__(self, sku: str):
        self.sku = sku


@app.exception_handler(OutOfStock)
def out_of_stock_handler(request: Request, exc: OutOfStock):
    return JSONResponse(
        status_code=409,
        content={"error": f"{exc.sku} is out of stock"},
    )


@app.post("/buy/{sku}")
def buy(sku: str):
    raise OutOfStock(sku)        # caught by the handler above
Try it
Add a handler for Pydantic's RequestValidationError to reshape 422 responses into your own format.

Custom response types

Return more than JSON when you need to: HTML, redirects, files, or streams. Import the response classes from fastapi.responses.

main.py
from fastapi import FastAPI
from fastapi.responses import (
    HTMLResponse,
    RedirectResponse,
    PlainTextResponse,
    StreamingResponse,
)

app = FastAPI()


@app.get("/page", response_class=HTMLResponse)
def page():
    return "<h1>Hello</h1><p>Rendered as HTML.</p>"


@app.get("/old")
def old():
    return RedirectResponse(url="/page", status_code=307)


@app.get("/robots.txt", response_class=PlainTextResponse)
def robots():
    return "User-agent: *\nDisallow:"


@app.get("/stream")
def stream():
    def generate():
        for i in range(5):
            yield f"chunk {i}\n"
    return StreamingResponse(generate(), media_type="text/plain")
Try it
Build a StreamingResponse that yields rows from a large CSV so the client starts receiving data immediately.

Dependency injection

Dependencies are reusable functions whose results FastAPI injects into your routes. Declare them with Depends. This is the backbone of clean FastAPI code: shared logic in one place, requested by signature.

main.py
from typing import Annotated
from fastapi import FastAPI, Depends

app = FastAPI()


# A dependency is just a callable.
def pagination(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}


Pagination = Annotated[dict, Depends(pagination)]   # reusable alias


@app.get("/items")
def list_items(page: Pagination):
    return {"querying": page}


@app.get("/users")
def list_users(page: Pagination):     # same logic, zero duplication
    return {"querying": page}

Classes as dependencies

main.py
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()


class CommonParams:
    def __init__(self, q: str | None = None, limit: int = 10):
        self.q = q
        self.limit = limit


@app.get("/search")
def search(params: Annotated[CommonParams, Depends()]):
    return {"q": params.q, "limit": params.limit}

Sub-dependencies

A dependency can itself depend on others. FastAPI resolves the whole graph and caches each dependency per request.

main.py
from typing import Annotated
from fastapi import Depends, Header, HTTPException


def get_token(x_token: Annotated[str | None, Header()] = None) -> str:
    if not x_token:
        raise HTTPException(401, "Missing X-Token header")
    return x_token


def get_current_user(token: Annotated[str, Depends(get_token)]) -> dict:
    # token is resolved first, then passed in here
    return {"id": 1, "token": token}


@app.get("/me")
def me(user: Annotated[dict, Depends(get_current_user)]):
    return user
Try it
Add the dependency at the router or app level via dependencies=[Depends(get_token)] to enforce it everywhere without naming it in each function.

Dependencies with yield (cleanup)

A dependency that yields can run setup, hand over a value, and run teardown afterward — the canonical pattern for opening and closing a database session per request.

main.py
from typing import Annotated, Generator
from fastapi import Depends, FastAPI

app = FastAPI()


def get_db() -> Generator:
    db = {"connection": "open"}      # imagine SessionLocal()
    print("open db")
    try:
        yield db                     # value handed to the route
    finally:
        print("close db")           # always runs, even on error


@app.get("/items")
def list_items(db: Annotated[dict, Depends(get_db)]):
    return {"db_state": db["connection"]}
Note
Code after yield runs once the response is sent. Always wrap it in try/finally so cleanup happens even when the route raises.

Bigger apps: APIRouter & structure

Splitting one giant main.py into routers keeps a growing app sane. Each domain gets its own module with an APIRouter; main.py stitches them together.

main.py
# app/routers/items.py
from fastapi import APIRouter

router = APIRouter(prefix="/items", tags=["items"])


@router.get("")
def list_items():
    return ["pen", "notebook"]


@router.get("/{item_id}")
def get_item(item_id: int):
    return {"item_id": item_id}
main.py
# app/main.py
from fastapi import FastAPI
from app.routers import items, users

app = FastAPI(title="My Store API")

app.include_router(items.router)
app.include_router(users.router)


@app.get("/")
def root():
    return {"status": "ok"}

file
app/
├─ main.py            # creates FastAPI(), includes routers

Settings & configuration

Never hardcode secrets. pydantic-settings reads configuration from environment variables (and a .env file) into a typed, validated object.

terminal
pip install pydantic-settings
main.py
# config.py
from functools import lru_cache
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_name: str = "My API"
    database_url: str
    secret_key: str
    debug: bool = False

    model_config = SettingsConfigDict(env_file=".env")


@lru_cache                  # build once, reuse everywhere
def get_settings() -> Settings:
    return Settings()
main.py
# main.py
from typing import Annotated
from fastapi import Depends, FastAPI
from config import Settings, get_settings

app = FastAPI()


@app.get("/info")
def info(settings: Annotated[Settings, Depends(get_settings)]):
    return {"app": settings.app_name, "debug": settings.debug}

Database CRUD with SQLModel

SQLModel (by FastAPI's author) unifies your table model and your Pydantic model. One class is both an ORM table and a validated schema.

terminal
pip install sqlmodel
main.py
# database.py
from sqlmodel import SQLModel, create_engine, Session

engine = create_engine("sqlite:///app.db", echo=True)


def init_db():
    SQLModel.metadata.create_all(engine)


def get_session():
    with Session(engine) as session:
        yield session
main.py
# models.py
from sqlmodel import SQLModel, Field


class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    secret_name: str
    age: int | None = None
main.py
# main.py
from typing import Annotated
from contextlib import asynccontextmanager
from fastapi import FastAPI, Depends, HTTPException
from sqlmodel import Session, select

from database import engine, init_db, get_session
from models import Hero


@asynccontextmanager
async def lifespan(app: FastAPI):
    init_db()            # create tables on startup
    yield


app = FastAPI(lifespan=lifespan)
DbSession = Annotated[Session, Depends(get_session)]


@app.post("/heroes", response_model=Hero)
def create_hero(hero: Hero, session: DbSession):
    session.add(hero)
    session.commit()
    session.refresh(hero)        # populate the new id
    return hero


@app.get("/heroes", response_model=list[Hero])
def list_heroes(session: DbSession, offset: int = 0, limit: int = 20):
    return session.exec(select(Hero).offset(offset).limit(limit)).all()


@app.get("/heroes/{hero_id}", response_model=Hero)
def get_hero(hero_id: int, session: DbSession):
    hero = session.get(Hero, hero_id)
    if not hero:
        raise HTTPException(404, "Hero not found")
    return hero


@app.delete("/heroes/{hero_id}")
def delete_hero(hero_id: int, session: DbSession):
    hero = session.get(Hero, hero_id)
    if not hero:
        raise HTTPException(404, "Hero not found")
    session.delete(hero)
    session.commit()
    return {"deleted": hero_id}
Try it
Add a PATCH /heroes/{id} route. Read the hero, apply only the fields the client sent (use hero_update.model_dump(exclude_unset=True)), then commit.
Note
For high-concurrency production apps, look at the async engine (create_async_engine) with asyncpg. The synchronous version above is perfect for learning and many real apps.

OAuth2 password flow + JWT

This is the standard token login for FastAPI: the user posts a username and password, you verify them, and you return a signed JWT the client sends back on every protected request.

terminal
pip install "passlib[bcrypt]" "python-jose[cryptography]"
main.py
from datetime import datetime, timedelta, timezone
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from jose import JWTError, jwt
from passlib.context import CryptContext

SECRET_KEY = "change-me-to-a-long-random-string"
ALGORITHM = "HS256"
EXPIRE_MINUTES = 30

app = FastAPI()
pwd = CryptContext(schemes=["bcrypt"], deprecated="auto")
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

# Pretend DB; password is the bcrypt hash of "secret"
FAKE_USERS = {
    "alice": {"username": "alice", "hashed": pwd.hash("secret")},
}


def authenticate(username: str, password: str):
    user = FAKE_USERS.get(username)
    if not user or not pwd.verify(password, user["hashed"]):
        return None
    return user


def create_token(data: dict) -> str:
    payload = data.copy()
    payload["exp"] = datetime.now(timezone.utc) + timedelta(minutes=EXPIRE_MINUTES)
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)


@app.post("/token")
def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user = authenticate(form.username, form.password)
    if not user:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Bad credentials")
    return {"access_token": create_token({"sub": user["username"]}),
            "token_type": "bearer"}


def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    creds_error = HTTPException(
        status.HTTP_401_UNAUTHORIZED,
        "Invalid token",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username = payload.get("sub")
    except JWTError:
        raise creds_error
    user = FAKE_USERS.get(username)
    if not user:
        raise creds_error
    return user


@app.get("/me")
def read_me(user: Annotated[dict, Depends(get_current_user)]):
    return {"username": user["username"]}
Try it
Open /docs. Because you used OAuth2PasswordBearer, an Authorize button appears — log in as alice / secret, then call /me.
Note
Hash passwords with bcrypt, never store plaintext. Keep SECRET_KEY out of code (load it from settings) and rotate it if leaked.

Simple API-key auth

For service-to-service calls, a header API key is often enough. Enforce it with a dependency — reuse it per-route or app-wide.

main.py
from typing import Annotated
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import APIKeyHeader

app = FastAPI()
api_key_header = APIKeyHeader(name="X-API-Key")
VALID_KEYS = {"key-123", "key-456"}


def require_api_key(key: Annotated[str, Depends(api_key_header)]):
    if key not in VALID_KEYS:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "Invalid API key")
    return key


@app.get("/private", dependencies=[Depends(require_api_key)])
def private():
    return {"data": "secret"}
Try it
Call /private without the X-API-Key header (403), then with a valid one (200).

async def vs def — choose correctly

FastAPI supports both. The rule is about what the function does, not preference:

  • Use async def when you await non-blocking I/O (async DB drivers, httpx.AsyncClient, async queues).
  • Use plain def when you call blocking libraries (most ORMs, requests, file I/O). FastAPI runs these in a threadpool so they don't block the event loop.
  • The cardinal sin: calling a blocking function inside async def — it freezes the whole server.
main.py
import asyncio
import time
from fastapi import FastAPI

app = FastAPI()


@app.get("/async-good")
async def async_good():
    await asyncio.sleep(1)        # non-blocking: server stays responsive
    return {"ok": True}


@app.get("/sync-good")
def sync_good():
    time.sleep(1)                 # blocking, but runs in a threadpool -> fine
    return {"ok": True}


@app.get("/async-bad")
async def async_bad():
    time.sleep(1)                 # BLOCKING inside async -> freezes everything
    return {"ok": False}
Note
When unsure, use plain def. FastAPI handles the threadpool for you, and it's the safe default.

Background tasks

Return the response immediately and finish slow work afterward — sending email, writing logs — with BackgroundTasks.

main.py
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()


def write_log(message: str):
    with open("app.log", "a") as f:
        f.write(message + "\n")


@app.post("/signup")
def signup(email: str, tasks: BackgroundTasks):
    tasks.add_task(write_log, f"new signup: {email}")
    return {"message": "Check your inbox"}     # returns before the log writes
Note
BackgroundTasks run in the same process — great for quick jobs. For heavy or retryable work, reach for Celery, ARQ, or a real task queue.

Custom middleware

main.py
import time
from fastapi import FastAPI, Request

app = FastAPI()


@app.middleware("http")
async def add_timing_header(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)        # run the route
    response.headers["X-Process-Time"] = f"{time.perf_counter() - start:.4f}"
    return response

FastAPI speaks WebSockets for realtime, bidirectional communication — chat, live dashboards, notifications.

from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws")
async def websocket_endpoint(ws: WebSocket):
    await ws.accept()

        while True:

        print("client disconnected")

A tiny broadcast manager

main.py
class ConnectionManager:
    def __init__(self):
        self.active: list[WebSocket] = []

    async def connect(self, ws: WebSocket):
        await ws.accept()
        self.active.append(ws)

    def disconnect(self, ws: WebSocket):
        self.active.remove(ws)

    async def broadcast(self, message: str):
        for ws in self.active:
            await ws.send_text(message)


manager = ConnectionManager()


@app.websocket("/chat")
async def chat(ws: WebSocket):
    await manager.connect(ws)
    try:
        while True:
            msg = await ws.receive_text()
            await manager.broadcast(msg)
    except WebSocketDisconnect:
        manager.disconnect(ws)
Try it
Open two browser tabs with a tiny JS new WebSocket("ws://localhost:8000/chat") client and watch messages broadcast between them.

Lifespan events (startup / shutdown)

Run code once when the app boots and once when it stops — connect a database pool, warm a cache, load an ML model. The modern API is lifespan (it replaced the old @app.on_event).

main.py
from contextlib import asynccontextmanager
from fastapi import FastAPI

ml_models = {}


@asynccontextmanager
async def lifespan(app: FastAPI):
    # --- startup ---
    ml_models["model"] = lambda x: x * 2     # imagine loading a real model
    print("startup complete")
    yield
    # --- shutdown ---
    ml_models.clear()
    print("shutdown complete")


app = FastAPI(lifespan=lifespan)


@app.get("/predict")
def predict(value: int):
    return {"result": ml_models["model"](value)}
Note
Everything before yield runs at startup; everything after runs at shutdown. Resources loaded here are available to all routes.

OpenAPI & docs customization

Your docs are generated from an OpenAPI schema you can shape: app metadata, per-route summaries, tags, deprecation, and example payloads.

main.py
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI(
    title="Store API",
    description="A demo API for the FastAPI guide.",
    version="1.2.0",
    contact={"name": "API Team", "email": "api@example.com"},
)


class Item(BaseModel):
    name: str = Field(examples=["Wireless Mouse"])
    price: float = Field(examples=[29.99])


@app.post(
    "/items",
    tags=["items"],
    summary="Create an item",
    description="Adds a new item to the catalogue and returns it.",
    response_description="The created item",
)
def create_item(item: Item):
    return item


@app.get("/legacy", deprecated=True)
def legacy():
    return {"note": "use /items instead"}
Note
The raw schema lives at /openapi.json. Point client generators, Postman, or other tools at it to scaffold SDKs automatically.

Deployment

In development you use fastapi dev. In production, run an ASGI server explicitly and put it behind a reverse proxy (Nginx, a load balancer, or your platform's router).

terminal
# Production server (multiple worker processes)
fastapi run main.py --workers 4

# Equivalent with uvicorn directly
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4

Dockerfile

file
FROM python:3.12-slim

WORKDIR /code

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY ./app ./app

EXPOSE 8000
CMD ["fastapi", "run", "app/main.py", "--port", "8000"]
  • Set the worker count near your CPU core count; measure, don't guess.
  • Terminate TLS at the proxy and pass --proxy-headers so FastAPI sees the real client scheme and IP.
  • Load secrets from the environment, run with DEBUG=false, and ship structured logs.
  • Add a /health endpoint for load-balancer and container health checks.
Try it
Build the image and run it: docker build -t myapi . && docker run -p 8000:8000 myapi, then open /docs on the running container.

Best practices & where to go next

You've covered the full surface of FastAPI. The habits that separate solid APIs from fragile ones:

  • Separate input and output schemas. A UserCreate is not a UserPublic. Keep them distinct.
  • Push shared logic into dependencies. Auth, pagination, DB sessions — declare them, don't repeat them.
  • Validate at the edge. Let Pydantic reject bad data before it reaches your business logic.
  • Type everything. The richer your hints, the better your validation, docs, and editor support.
  • Test the contract. A TestClient test per route catches regressions cheaply.
  • Keep secrets in the environment and never commit your .env.

Read next: the official docs at fastapi.tiangolo.com (the tutorial and “Advanced User Guide”), plus the SQLModel and Starlette docs for the layers beneath FastAPI.
